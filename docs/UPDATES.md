# Обновление базы (M6)

## Модель распространения: что публикуется, а что нет

| Компонент | Где живёт |
|---|---|
| Код приложения (TS, тесты, скрипты, документация) | публичный репозиторий GitHub (`songbook-offline`) |
| Собранная база `songs.db` (~142 МБ) | только на компьютере владельца |
| APK с базой | собирается локально (`npm run android:apk`), ставится на своё устройство |
| Дельта-пакеты `delta-<версия>.json.gz` | собираются локально, переносятся на телефон файлом |

Причина: база содержит тексты и аккорды произведений. Публикация базы или APK с ней —
это распространение, а не личная копия. Код публиковать безопасно, данные — нет.

Следствие: приложение не скачивает первичную базу из интернета — она вшита в APK,
который собирается у владельца. Из сети приходят только новые песни и обновления.

## Режимы обновления в приложении

Все три режима запускаются вручную, фонового трафика нет.

### 1. «Обновить с сайта» — основной режим

Читает первые страницы списка `/lang/2`, сравнивает id с локальным набором и докачивает
10–30 песен, которых в базе нет. Полминуты, несколько сотен КБ.

Важно: список на сайте **не отсортирован по id** (проверено: на первой странице максимум 85904,
при этом в базе есть id до 88949), поэтому определять новое по `max(id)` нельзя — только
по составу.

### 2. «Обновить избранное» и кнопка ⟳ на экране песни

- «Обновить избранное» перекачивает только отмеченные звездой песни — так подхватываются
  правки текста и смены тональности.
- Кнопка ⟳ на экране песни обновляет одну песню: сравнивает текст с локальной копией
  и, если он изменился, записывает новую версию.

### Почему нет кнопки «проверить весь каталог»

Полный обход — 43 000 страниц по ~280 КБ, то есть ~12 ГБ трафика: сайт не поддерживает
`If-Modified-Since`/ETag (проверено: условный запрос возвращает 200 и полный HTML).
Поэтому массовое обновление делается на компьютере и приходит с новой версией APK,
а точечные правки подтягиваются избранным или отдельной песней.

### 3. «Обновить из файла» — резервный режим

Если интернета нет, пакет собирается на компьютере:

```bash
npm run crawl -- --lang=ru
npm run db:build -- --in=data/raw/ru.jsonl --version=2026-11-01
npm run delta:build -- \
  --old=data/raw/ru-2026-10-26.jsonl \
  --new=data/raw/ru.jsonl \
  --from=2026-10-26 --to=2026-11-01
```

`data/build/delta-2026-11-01.json.gz` переносится на телефон, в приложении:
**Настройки → Дополнительно → Обновить из файла**.

### 3. Полная пересборка (раз в несколько месяцев)

```bash
npm run db:build && npm run db:install && npm run android:apk
```

APK переустанавливается поверх — база заменяется целиком.

## Дополнительно: GitHub Releases (необязательный режим)

Если когда-нибудь появится разрешение правообладателей на публикацию базы, режим
«Проверить обновления» по манифесту уже готов: `npm run delta:build --base-url=…`
и `npm run release:publish --repo=…`. Пока этот режим не используется, потому что
ассеты приватного репозитория требуют токена, а публичные — означают раздачу данных.

## Технические решения

| Решение | Почему |
|---|---|
| `INSERT OR REPLACE` вместо `UPSERT` | на Android 6.0 системный SQLite старше `ON CONFLICT DO UPDATE` |
| FTS4 + `INSERT INTO songs_fts(songs_fts) VALUES('rebuild')` | FTS5 есть не на всех прошивках, `rebuild` безопасно пересобирает индекс |
| `CapacitorHttp.enabled = true` | у сайта нет CORS-заголовков, обычный fetch из WebView блокируется |
| База копируется из `assets/songs.db` в `songsSQLite.db` | плагин SQLite открывает `getDatabasePath(dbName + "SQLite.db")` |
| Дельта собирается по хэшу `key + text` | правка одной строки меняет хэш и попадает в пакет |
